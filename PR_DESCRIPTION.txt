# Fix MoE Segfault and Enable SM121 Support

## Summary
This PR fixes a segmentation fault in `test_moe_mxfp8_mxfp4` and enables SM121 device compatibility with SM120 kernel configurations.

## Issues Fixed

### 1. Segfault when MoE tactics vector is empty
**Problem:** Code was calling `.front()` on empty `mAllProfiles` vector, causing segfault when no valid CUTLASS kernels exist for a dtype combination.

**Solution:** Added safety check in `FusedMoeRunner` constructor immediately after `getTactics()`:
```cpp
TVM_FFI_ICHECK(!mAllProfiles.empty())
    << "No valid tactics available for fused moe op with the requested input combination Activation: "
    << DLDataTypeToString(mActivationDtype)
    << ", Weight: " << DLDataTypeToString(mWeightDtype)
    << ", Output: " << DLDataTypeToString(mOutputDtype);
```

**Impact:**
- Prevents segfaults for any unsupported dtype combination (not just MXFP8xMXFP4)
- Provides clear error message to guide users
- Follows same pattern as `TrtllmGenGemmRunner` and `TrtllmGenBatchedGemmRunner`

### 2. SM121 cannot use SM120 kernel configurations
**Problem:** SM121 devices were failing with "Using SM 120 configuration for SM 121 device" error, despite being architecturally identical.

**Solution:** Refactored SM compatibility check into cleaner lambda with proper compatibility matrix:
- SM100 configs → work on SM100, SM103, SM110, SM120, SM121
- SM120 configs → work on SM120, SM121

**Impact:**
- NVFP4 tests now pass on SM121 devices
- Cleaner, more maintainable code
- Easy to extend for future SM versions

### 3. Mark test_moe_mxfp8_mxfp4 as expected failure
**Reason:** MXFP8xMXFP4 kernel not yet implemented on SM120/121 (only NVFP4 is available).

**Marked as `xfail`** instead of `skip`:
- Shows it's expected to fail until implementation is complete
- Will automatically pass when kernels are added
- Keeps test visible in test suite
